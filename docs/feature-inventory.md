# Feature Inventory: Original Bluey (GooglyEyes) & Flash Windows/Android Port

This document provides a complete, line-by-line verified inventory of all features in the original Apple-native Bluey project (`GooglyEyes.xcodeproj`, `Mac/`, `iOS/`, `Shared/`), their source file references, exact runtime behaviors, proposed cross-platform ports for Windows and Android, and concrete acceptance tests.

## 1. Visual Identity, Aesthetics & Tokens

### 1.1 Color Palette & Theme Tokens
- **Status**: Implemented and tested
- **Source Files**: [`Shared/Palette.swift:1-21`](file:///c:/Keerthu/flash/flash/Shared/Palette.swift#L1-L21), [`iOS/Sources/BlobShape.swift:1-35`](file:///c:/Keerthu/flash/flash/iOS/Sources/BlobShape.swift#L1-L35)
- **Original Behavior**:
  - Defines fixed hex palette constants: `berry1` (0xA9BCFF, light periwinkle), `berry2` (0x6C86F5), `berry3` (0x4254D6), `berry4` (0x2B2F8F, deep indigo), `nose` (0x1C1F66), `ink` (0x17151F), `inkSoft` (0xB9B2CC), `panel` (0x1E1B29).

  - 4-stop linear gradient at 150° from `berry1` to `berry4` with stop positions `[0, 0.34, 0.68, 1.0]`.
- **Proposed Flash Port**:
  - Rebrand from Bluey blueberry to **Flash the Sloth**: warm moss, lichen, honey, chestnut, and eucalyptus palette (`slothGold: #E5A93C`, `slothFur: #5C4333`, `slothCream: #EADBC8`, `slothMoss: #5B8C5A`, `slothDark: #1F1916`, `accentEmerald: #34D399`).

- **Acceptance Test**:
  - Inspect phone interface and desktop overlay canvas: theme tokens render consistently across CSS styles, WebGL 3D sloth material shaders, and SVG accents without unstyled color fallbacks.

## 2. Networking, Protocol & Pairing

### 2.1 Service Discovery
- **Status**: Implemented and tested
- **Source Files**: [`Shared/GooglyLink.swift:6-8`](file:///c:/Keerthu/flash/flash/Shared/GooglyLink.swift#L6-L8), [`iOS/Sources/MacLink.swift:28-45`](file:///c:/Keerthu/flash/flash/iOS/Sources/MacLink.swift#L28-L45), [`Mac/Sources/GooglyMac/PhoneServer.swift:22-38`](file:///c:/Keerthu/flash/flash/Mac/Sources/GooglyMac/PhoneServer.swift#L22-L38)
- **Original Behavior**:
  - Uses Apple Network.framework Bonjour service advertisement with type `_googly._tcp` and `NWBrowser`.
- **Proposed Flash Port**:
  - Windows Python agent advertises service `_flash._tcp.local.` via `zeroconf`.
  - Android browser (PWA) cannot directly run mDNS discovery over raw sockets; therefore, provide:
    1. Direct LAN IP entry with auto-subnet scanning via fetch probes.
    2. QR code generated by Windows agent showing `ws://<LocalIP>:<Port>/ws?token=<AuthToken>`.
    3. Auto-reconnection to stored last-known IP.
- **Acceptance Test**:
  - Scanning the laptop's terminal or tray QR code on Redmi phone connects the WebSocket within 1.5 seconds. Reopening the PWA reconnects automatically.

### 2.2 Wire Protocol & Packet Framing
- **Status**: Implemented and tested
- **Source Files**: [`Shared/GooglyLink.swift:33-134`](file:///c:/Keerthu/flash/flash/Shared/GooglyLink.swift#L33-L134)
- **Original Behavior**:
  - Newline-delimited JSON (0x0A delimiter) over raw TCP connection (`LineConnection`).
  - Packet fields: `face` (`FaceState`), `hello`, `volume`, `command`, `audio`, `speech`, `callID`, `tool`, `text`, `image`.
- **Proposed Flash Port**:
  - Standards-compliant WebSocket connection using JSON messages over `ws://<IP>:<Port>/ws`.
  - Same packet semantics preserved and extended:
    - `face`: `{ gazeX: float, gazeY: float, mood: string, talk: float }`
    - `command`: `wake`, `sleep`, `caption`, `captionDone`, `tool`, `toolResult`, `transcribe`, `notes`, etc.
    - `callId`: correlation ID for request/response pairing.
    - Authentication handshake via initial ticket/token.
- **Acceptance Test**:
  - Transmit 100 consecutive face gaze updates and 10 tool request/response cycles. Zero dropped frames, zero corrupted JSON parses, average round-trip latency < 15ms on local Wi-Fi.

## 3. Facial Expression & Gaze Animation Engine

### 3.1 Physics Spring Simulation
- **Status**: Implemented and tested
- **Source Files**: [`iOS/Sources/FaceView.swift:3-21, 41-52`](file:///c:/Keerthu/flash/flash/iOS/Sources/FaceView.swift#L3-L21)
- **Original Behavior**:
  - Second-order damped spring system: `velocity += (stiffness * (target - value) - 2 * sqrt(stiffness) * damping * velocity) * dt`.
  - Distinct stiffness/damping parameters for gazeX (260/0.82), gazeY (260/0.82), pupil (160/0.5), browLift (180/0.55), browTilt (150/0.6), lean (60/0.8), hop (260/0.35), blush (40/1.0), squint (150/0.7).
- **Proposed Flash Port**:
  - Port `Spring` math to TypeScript animation loop running on `requestAnimationFrame`. Drive Three.js bone rotations and morph targets.
- **Acceptance Test**:
  - Step response test for gaze coordinate jump from -1.0 to +1.0 exhibits realistic overshoot and settling time matching the original Swift implementation.

### 3.2 Eye Saccades, Jitter & Blinking
- **Status**: Implemented and tested
- **Source Files**: [`iOS/Sources/FaceView.swift:55-64, 102-114, 154-165`](file:///c:/Keerthu/flash/flash/iOS/Sources/FaceView.swift#L55-L64)
- **Original Behavior**:
  - Idle wander targets randomized every 0.6–2.2 seconds.
  - Micro-jitter (0.015–0.07 magnitude) applied every 0.5–1.4 seconds.
  - Blinks triggered every 2.0–5.0 seconds (drowsy 1.6–3.0s); 25% chance of double-blink. Drowsy blinks take 0.7s vs 0.15s normal.
- **Proposed Flash Port**:
  - Fully ported to the Three.js Flash character controller. Sloth eye blinks have customizable drowsiness factor.
- **Acceptance Test**:
  - Character blinks autonomously without freezing main thread; double blinks occur stochastically; gaze wanders during idle states.

### 3.3 Emotional Mood States
- **Status**: Implemented and tested
- **Source Files**: [`Shared/GooglyLink.swift:10-14`](file:///c:/Keerthu/flash/flash/Shared/GooglyLink.swift#L10-L14), [`iOS/Sources/FaceView.swift:124-171, 264-358`](file:///c:/Keerthu/flash/flash/iOS/Sources/FaceView.swift#L124-L171)
- **Original Behavior**:
  - 7 moods: `listening`, `resting`, `thinking`, `talking`, `pointing`, `happy`, `sleepy`.
  - Visual expressions:
    - `listening`: enlarged pupils (1.12), lifted brows (+10).
    - `talking`: dynamic brow lift (6 + talk*18), mouth opening, tongue showing when talk > 0.25.
    - `pointing`: narrowed pupils (0.95), brow tilt (-0.14), focused upper eyelid droop.
    - `thinking`: eyes look up and right, brows tilted (+0.22), 3 floating animated thought dots.
    - `happy`: large pupils (1.2), arched high brows (+16), pink blush cheeks (0.85), bottom eyelid squinting up, smiling mouth.
    - `resting`: shut downward curve eyes, floating 'z' nap particles, slow breathing cycle.
    - `sleepy`: heavy droopy upper eyelids with sinusoidal oscillation, pupils sinking downward, slow blinks.
- **Proposed Flash Port**:
  - 3D sloth rig with blendshapes for `squint`, `blink`, `browInnerUp`, `browSlant`, `jawOpen`, `smile`, and particle systems for thought bubbles and 'z' sleep particles.
- **Acceptance Test**:
  - Switching state packet to each of the 7 moods triggers the exact morph target transitions with smooth spring interpolation.

### 7.4 Built-In Guardrails & Safety Refusals
- **Status**: Implemented and tested
- **Source Files**: [`Mac/Sources/GooglyMac/RealtimeHost.swift:320-335, 636-650`](file:///c:/Keerthu/flash/flash/Mac/Sources/GooglyMac/RealtimeHost.swift#L320-L335)
- **Original Behavior**:
  - Refuses to interact with password fields.
  - Refuses lock/logout/force-quit shortcuts (`cmd+shift+q`, `ctrl+cmd+q`, `cmd+option+esc`).
  - Stop hotkey (`⌃⌥S`) immediately aborts actions and locks automation for 6 seconds.
  - Strict instruction rule: On-screen text is treated as information, never instructions (prompt injection prevention).
- **Proposed Flash Port**:
  - Windows port strictly implements:
    1. Refusal of fields with `IsPassword == True`.
    2. Refusal of Windows destructive combos (`win+l` lock, `alt+f4` without confirmation, `ctrl+alt+del`).
    3. Global emergency stop circuit that halts all action immediately.
    4. Confirmation required before hard-to-undo actions (organizing/moving files, closing windows).
- **Acceptance Test**:
  - Attempting `win+l` returns blocked guardrail error; unconfirmed `alt+f4` or file organization demands confirmation; emergency stop halts agent immediately.
